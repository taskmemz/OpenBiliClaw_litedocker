# Eval Reason Diet Spec — cut evaluation output tokens safely

**Created:** 2026-07-18
**Corrected:** 2026-07-28
**Scope:** the `reason` field in batch/single content-evaluation prompts, its
parser/storage contract, and the production-equivalent replay quality gate.

## Goal

Every evaluation item previously emitted a free-text reason even when its score
was too low to enter the recommendation pool. The change makes `score < 0.5`
emit an empty reason and caps the remaining diagnostic reason at 30 Chinese
characters. Expected output-token reduction is 30–50% on low-score-heavy
batches; the actual effect must be observed with `openbiliclaw cost --by caller`.

Evaluator `relevance_reason` is internal diagnostic metadata. Recommendation
copy and delight copy are generated by their own paths; the current delight
fallback does not surface evaluator reasons.

## Design invariants

1. The skip floor is fixed in static system-prompt text so each caller retains
   a byte-stable cache prefix.
2. Supported `[discovery].admission_min_score` values are `[0.5, 1]`; invalid
   lower values fall back to `0.60`. Explore remains `0.58`. Therefore a score
   below `0.5` cannot enter any supported admission path.
3. Missing/empty `reason` continues to normalize to `""`; cache and candidate
   persistence accept it.
4. At/above `0.5`, `reason` remains one conversational sentence of at most
   30 Chinese characters for bounded diagnostic output.
5. Quality is decided by one frozen, auditable replay run, not by comparing
   independent commands or by an absolute threshold that ignores provider
   noise.

## Replay gate

Run at least 100 of the most recent production-mix candidates across
`evaluated`, `cached`, and `rejected_low_score`:

```bash
.venv/bin/python scripts/run_profile_diet_ab.py \
  --arm-b reason-diet \
  --sample 100 \
  --repeats 3 \
  --db /path/to/openbiliclaw.db \
  --config /path/to/config.toml \
  --output data/eval/reason-diet.json
```

The command:

- opens the candidate DB read-only and uses a run-scoped embedding cache;
- freezes candidates, profile, and negative exemplars for all pairs;
- uses the same source context and production `max_tokens=4096` for both arms;
- alternates A/B execution order and repeats both A/A and A/B at least three
  times;
- fails loudly on timeouts, incomplete vectors, or missing parsed responses
  instead of turning infrastructure failures into zero-score observations;
- writes candidate IDs, snapshot digests, raw paired scores, model routes,
  usage, and derived gate metrics to the required JSON artifact.

The relative gate compares treatment medians with the repeated A/A empirical
envelope. It requires treatment flip rate and Spearman to stay within that
envelope (with the 3% / 0.95 absolute bounds when stricter), and rejects an
admission-rate contraction more than 3 percentage points below the control
median.

## Superseded result

The 2026-07-18 result previously recorded as `PASS` is invalid and must not be
used as merge evidence. Its A/A and A/B arms used different `source_context`
values, separate snapshots, a replay-only 16384-token ceiling, and no executable
relative-gate enforcement; sampling also reweighted platform/strategy groups.
These defects can conceal drift and production gateway failures. A fresh
artifact from the corrected command above is required before merge.
